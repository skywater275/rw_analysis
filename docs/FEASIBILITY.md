## 二、按用途分档（★ 关键结论）

### ✅ 档 1：**读代码 / 学习 / 审计** —— 完全可行

- 类名 **86.8% 可读** ✓ ⇒ 能看懂「哪个类是干什么的」
- 包结构完整（71 个包 ✓）、逻辑完整（21.8 万行 ✓）、可编译（0 错误 ✓）
- **限制** ✗：成员名只有 **18% 可读** ⇒ 方法/字段名多为 `a`/`b`/`c` ⇒ **读逻辑容易、读语义难** ✓
- 缓解 ✓：`supplement.csv` 7,800 条可查；14 篇域文档可按功能定位

### ✅ 档 2：**改逻辑 / 做玩法模组 / 加功能** —— 高度可行

三条独立路径，**任选其一即可开发**：

1. **纯数据模组**（**最省力、风险最低** ✓）：改 `assets/units/*.ini` ✓ ——
   单位属性、武器、逻辑布尔表达式全在 INI 里 ✓ ⇒ **不需要碰 Java** ✓
2. **改 Java 源码** ✓：在 `03-deobfuscated/` 里改 ⇒ `javac_gate` 验证（**0 错误基线** ✓）
   ⇒ 走构建管线出 jar ⇒ **V0–V8 验收**（含真窗口 + 回放）✓
   ★ 有现成的**回归网**：改完必须过 V5/V6 ✓ ⇒ **不会悄悄改坏游戏** ✓
3. **写外部工具** ✓：MCP 游戏服务器（脚本通道 + 297 工具）可**动态驱动游戏** ✓
   ⇒ 做数据采集、自动化测试、AI 对手、录像分析等 ✓

### ⚠️ 档 3：**从零纯净重建整个 jar** —— 暂不可行

- 反向重建**只产出约一半类** ✗（旁路实建 **A 类 873** ✓ vs 交付物 **1,273** ✓）
- 剩下的是**累积池**里的历史产物 ✓ ⇒ 现状 jar 是「**累积态**」而非「一次重建态」✓
- 反向世界仍有 **31,263 条编译错误** ✗（阻塞约 **411 个类** ✗）
  - 主因族：`cannot find symbol` **411 类** ✗ · `getLabel` 覆写族 68 ✗ · `boolean/float cannot be dereferenced` 42 ✗
- **不影响档 1/档 2** ✓（那两档不需要纯净重建 ✓）

## 三、开发工作流建议（可直接照做 ✓）

```bash
# ① 改源码
#    在 03-deobfuscated/ 下编辑（类名基本可读 ✓）

# ② 编译门禁（必须 0 错误 ✓）
python tools/gates/javac_gate.py

# ③ 出 jar（旁路，不动交付物 ✓）
$env:RW_REVERSE_OUT_JAR='build/_dev-probe.jar（历史产物，已清理 ✓）'
python tools/fixers/build_reverse_jar.py --apply
python tools/fixers/build_conflict_pass.py --world all --include-skip --apply

# ④ 完整验收（含真窗口 + 回放 ✓）
python tools/gates/replacement_verify.py

# ⑤ 动态验证（可选 ✓）
python tools/rig/verify_rig.py          # 测试台现场校验 35 项
```

★ **铁律**（本项目已沉淀 ✓）：**任何改动都要过 V0–V8** ✓ ——
尤其 **V5 真窗口** 与 **V6 回放 0 分叉** ✓（结构性判据挡不住「结构合法但行为致命」的类 ✗）。

## 四、风险与注意事项

| 风险 | 说明 | 缓解 |
|---|---|---|
| **成员名混淆** ✗ | 18% 可读 ⇒ 改错成员名的概率高 | 用 `supplement` 查名 ✓ · 编译门禁 + 验收兜底 ✓ |
| **混合形态** ⚠️ | jar 里 75% 是我们的字节码、25% 是原版混淆字节 ⇒ 两边**必须行为一致** | 改动后**必跑 V5/V6** ✓ |
| **重建不完整** ✗ | 不能「删掉池重新生成」 | **不要清 `build/reverse-classes/`** ✓（清前必备份 ✓） |
| **映射跨宿主误改** ⚠️ | 本项目已知缺陷族（RS 系列 ✓）· 语义名→混淆名不校验宿主 | 见 `docs/PENDING.md` RS 小节 ✓ |
| **交付物 sha 会变** ⚠️ | 重打包后 zip 字节布局不同 ⇒ sha 变化（**内容等价** ✓） | 以「替换率 + 验收」为口径 ✓，不只看 sha ✓ |

## 五、结论

1. **档 1（读/学/审计）与档 2（改逻辑/模组/工具）都可行** ✓ —— 且**已有完整的验证网**（编译门禁 + V0–V8 + 真窗口 + 回放）✓，这在逆向项目里是**稀有的工程条件** ✓
2. **档 3（纯净重建）暂不可行** ✗ —— 卡在反向世界的 411 个类 ✗，属**已知、已量化、已入档**的缺口 ✓
3. **最推荐的第一步** ✓：从**纯数据模组**（`assets/units/*.ini` ✓）或**档 1 的代码阅读**入手 ✓ ——
   零风险、零构建依赖，且能立刻验证「这套源码是否够用」✓
