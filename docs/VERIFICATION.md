# 验收体系（V0–V8）

> 入口：`python tools/gates/replacement_verify.py` · 当前状态 **PASS 10 / FAIL 0 / BLOCKED 0** ✓

## 一、判据表

| 判据 | 检查什么 | 为什么需要 |
|---|---|---|
| **M0** | 产物指纹（sha / 大小） | 口径锚点 |
| **V0** | 环境复位（清 cache/ + crashes.txt） | 消除脏环境干扰 |
| **V1** | `javac_gate` 编译门禁 | `03` 树必须 **0 错误** |
| **V2** | `jar_compare_gate` 逐成员对照 | 与原版逐成员一致 |
| **V3** | `class_link_check` 内部 + 跨向引用 | **引用不存在的类不得超阈值**（≤4） |
| **V4** | 结构核对（成员集 / 构造器 / 多出成员） | 判「缺失成员」；多出成员只作信息 |
| **V4b** | 非 stock 条目无死件 | 防止产物里留下零引用孤儿 |
| **V5** | **GUI 真窗口冒烟** | ★ **结构合法 ≠ 行为正确** —— 唯一能抓「启动即崩」 |
| **V6** | **回放校验和**（`don't match`） | ★ 抓行为/状态分歧 |
| **V7** | 替换率（信息项） | 提量口径 |
| **V8** | **原子契约**（产物 == 池重打包） | 保证交付物可复现 |

## 二、判据分工（★ 关键认知）

1. **编译门禁（V1）** 保证「能编译」✗ 不保证「行为对」
2. **结构判据（V4）** 只比**成员集合** ⇒ **看不见**类头差异
   （实测：枚举类 `ACC_ENUM` 缺失、超类 `Object` vs 外层枚举 ⇒ V4 全过、V5 崩 ✗）
3. **运行时判据（V5 / V6）** 是**唯一**能挡「结构合法但行为致命」的一关 ✓
   - 已有先例：`game/units/custom/logicBooleans/LogicBooleanGameFunctions` 结构合法，**启动即崩** ✗
   - 枚举常量体：`VerifyError: Bad <init> method call` ✗ —— 源码形态无法表达，属**硬上限**

## 三、验收流程（收编候选时）

```
候选类 ⇒ ① V4 结构核对（剔结构不符）
        ⇒ ② 入池 + 重打包
        ⇒ ③ 完整验收 V0–V8（尤其 V5/V6）
        ⇒ ④ 不过则回滚（池从备份恢复）+ 记录负结果
```

★ **收编必须叠加运行时冒烟**：结构核对挡不住行为致命 ⇒ 二分定位（先排除一半、跑 V5、按 PASS/FAIL 收缩）。

## 四、负结果纪律

任何实验：
- **双度量**：可用类 **+** 编译错误行数 ✗ 单看一个会被假象骗
- **不达标即回退**，并在 `docs/PENDING.md` 记「勿重做」条目 ✓
